# 写方法 skill 的方法

## 一门学科一份

一份 skill 只装一门学科的一套方法：逻辑推理、因果推断、论证、反谄媚、需求读法、证据核验、工程计划……各自一份，各自调研，各自写全。两门学科的方法不合在一份里。用户点名的每个方法名，都必须落到某份 skill 的某一步，派工前逐条核对去处。没有调研的方法不写成 skill。

## 一份 skill 是什么

一份 skill 回答一个问题：手上有这些东西、要产出那样东西的时候，怎么一步一步做好。它是一个走法：几步动作，每步留下一样东西；留下的东西齐了，这一步就算做了。它不是规矩清单，不是词汇表，也不是输出模板。

skill 不属于任何角色。承担一件活的人一上手就把自己带的 skill 全读完、全带着，哪一步用哪份由他自己看眼前的事判断；工作流只写谁出场、交什么。所以 skill 里只写情形，不写角色名；「何时」只写"要做某件事之前"（要定下读法之前、要写"所以"之前、要说"做完了"之前），不写"谁在哪个阶段递来什么"。

## 形状（长度由方法决定）

```
---
name: <字母、数字、连字符>
description: Use when <何时用；第三人称；只写触发情形，不概括流程>
---
# <方法名>（<目录名>）
用于：手上有 <什么>，要产出 <什么> 的时候。
何时：<触发情形，用当事人眼前能看到的事写；不写角色名>
走法：
  1. <这一步做什么，用真实动作写：打开、跑、抄、写>
     怎么做：
       a. <子步骤：一个可执行的动作，带「做到什么程度算完成」的判据>
       b. …
       c. <做不到时怎么办>
     → 留下 <字段名>：<每一项装什么>。填不出：<这一步合法的「无法」写法，须带原因>
  2. …
做到了：<留下的东西齐了的判据，一两句>
为什么：<一句>
每一步来自哪个方法：<第 N 步 ← 方法名（可附原名）：一句说这个方法在这一步里怎么体现>
```

不写：出处、案例、禁令清单、"注意事项"、单独的输出模板——走法留下的字段就是这一步的表。

## 写全

方法要像论文里的方法一节：不只说这一步做什么，要说怎么做。凡是需要判断的步骤——列别的解释、造第二种读法、判一条反对意见够不够格、排顺序、分三类——都写出子步骤：每个子步骤是一个可执行的动作，带「做到什么程度算完成」的判据，最后一条是「做不到时怎么办」。只是机械动作的步骤（抄原话、贴输出）两句就够。

长度由方法决定，不设上限；也不加一句没有动作的话。判断写没写全的标准：把这一步交给一个没做过的人，他能不能照着子步骤做出同样的东西。

"为什么"只写一句。给理由不是为了让模型信服，是为了让它把方法用到没写到的情形上；没有理由的规则只会被按字面套，套不上就得再加一条。

## 引用别的学科

一步里要用另一门学科的方法时，不把那套方法抄进来，写一句引用，格式固定：「这一格照『某份』（那份的目录名）第 N 步写，写出 `字段`」。每份的标题后面带自己的目录名，引用时连目录名一起写，程序才核得出被引的那份在不在这一席的必读清单里。读的人手上已经有那一份，这句只告诉他这一格照哪份的哪一步写；那一步留下的字段要写进本步的「留下」里——没写出来就是没照着做。多步的方法只在它自己的学科那一份里写一遍；一行就写完的检查（抄下来的片段能在原文里逐字搜到）可以各处重复。

一句话同时触发几份的措辞阶梯（逻辑推理、因果推断、证据与核验各有一张）时，三处各算一级，句子按最低的那一级写。

## 语言

- 用一个没看过本项目任何文件的人也能照做的话写。每句只有一个意思。
- 本项目的内部说法一律不用。下面这些词及其同类，写成它们的白话：
  - 优先级翻译／分类翻译／并串翻译／三次翻译 → 排顺序／分三类／定先后
  - 承重 → 缺了它结论就变的
  - 停车场 → 暂不做的清单
  - 实做／实验证／浪费 → 直接改变结果的／证明某条完成条件的／删掉也不影响结果和证据的
  - 落点 → 改动所在的文件和行
  - 残留 → 留下的旧代码、兼容层、没人调用的定义
  - 痕迹 → 打开过的文件、跑过的命令和它的输出
  - 担保 → 从前提走到结论的那一步理由
  - 盲读 → 没看过对方那份时写下的读法
  - 反对卡 → 一条反对意见
  - 席位、门规、内核 → 不出现
- 项目里绕不开的名词，第一次出现时给一句说明，例如"契约（用户批过的目标和完成条件）"、"节点（计划里的一块活）"。
- 字段名用英文标识符，写在反引号里；正文里不用字段名代替话。
- 方法名可以带原名（如 Toulmin 三件套），但走法的每一步本身不靠方法名才能读懂。文末「每一步来自哪个方法」只是索引：方法的内容在走法的子步骤里，不在索引里。

## 字段规则

- 每个实质字段三态：**填了**（带来源：原话片段、打开的文件、命令输出）；**填不出**（带原因和缺的证据）；**不适用**（带依据）。三态进 enum，不用空串或 null 顶替任何一态。
- 多要痕迹，少要结论：引文、路径、原始输出优先；引文必须是原文的精确子串。
- 不设自证字段：置信度、严重度、"已检查：是"、"考虑过替代：是"，一律不设。
- 数组不设最少数量；空数组只表示"在所记录的范围内没找到"，范围要写。

## 三条铁律

1. **用产出代替禁令。**想写"别做 X"时，改成一步"留下 Y"，让 X 写不出来。
2. **出了事故不追加规则。**改走法、改字段、或改程序；skill 里不出现"另外注意……"。
3. **一步一物。**没有留下东西的步骤不是步骤，删掉。

## 写完自检

- 全文有没有角色名（中书、门下、尚书、执行体、御史、席位）？有就改成情形。
- 找一句最像行话的话，问：没看过本项目的人读得懂吗？读不懂就改白。
- 每一步都有动作、留下、填不出三件？
- 把所有"留下"抄出来，就是这一步的表？
- 每个需要判断的步骤都有「怎么做」的子步骤？交给没做过的人，能照着做出来吗？
- 有没有一句没有动作的话？有就删。
- 有没有一句是禁令、注意事项或自证？有就改成产出，或删掉。
- 有没有一段是别的学科的方法抄过来的？有就换成引用那一句。
- 「何时」里有没有"谁递来""哪个阶段"？有就改成"要做某件事之前"。

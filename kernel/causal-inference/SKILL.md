# 因果推断（causal-inference）
用到：逻辑推理（logical-reasoning）第 3 步；证据与核验（evidence-and-verification）。
用于：手上有材料，正要写下一句带"导致／造成／根因／责任在／改 X 会修好 Y"的话，并且这句会导出一个改动，或者指向某个人、某个团队。
何时：判的是要落笔的这一句话，不是这个话题。这句里有 导致、造成、使得、根因、归咎、责任；或者这句在说"改 X 会修好 Y／防住 Y"。只交代背景的"因为"不走这一份。
这条走法里每落一句话，它的前提、从前提走到结论的那一步理由、成立条件和限定，按「逻辑推理」（logical-reasoning）那一份做。

字段三态：填了（带来源）／填不出（带原因和缺的最小证据）／不适用（带依据，例如这句话不追究谁的责任，责任那一项就是不适用）。

走法：

1. 定下 X 有和没有的两种情况，再定下时间线。
   怎么做：
   a. 把 X 写成一个能被动手改的具体东西：哪个文件的哪一行、哪个配置项、哪个参数、哪一次提交。做到什么算完成：写完之后你能接着说出"把它改成什么"这句话；说不出来就是写空了（"配置有问题""系统异常"不算），换成能指出位置的写法。
   b. 写出 X 的两种状态：现在这一种 x，和用来对照的另一种 x′。把你打算保持不变的东西逐条列出来——同一份输入、同一个版本、同一台机器、同一个时间窗。做到什么算完成：x 和 x′ 并排写成两行，两行之间只有一处不同。有一样你保持不了，单独记下来，它以后要进第 4 步的"无法检验的假设"。
   c. 把 Y 写成一个别人能自己去看的东西：哪一条报错、哪个返回码、哪个数字超过多少、哪个文件有没有生成。做到什么算完成：换一个人拿着这句话去看，能回答"是"或"否"，或者报出一个数；做不到就再具体一层。
   d. 写清对象和范围：这句话管哪些情形——哪个模块、哪些用户、哪些输入、哪个版本区间；再写时间窗：从什么时候到什么时候之间发生的才算。做到什么算完成：有人举出一个例子时，你能指出它在范围内还是范围外。
   e. 做时间线：只用带时间戳的记录——日志行、提交时间、部署记录、监控点、文件修改时间。每行写成"时间戳｜发生了什么｜出处（文件路径加行号，或哪条命令的哪段输出）"。做到什么算完成：每一行都能指回一条记录；只能靠"先是……然后……"这种讲述才排得上的事，不进这张表，或者单独标成"没有时间戳"。
   f. 拿时间线回答一句：X 那一处的变化是不是发生在 Y 之前。时间戳分不出先后（同一秒、精度不够）就写"先后未定"。写完接着记一句：X 在前只排除了"是 Y 造成了 X"这一种，别的解释一个都还没排除。
   g. 做不到时：拿不到时间戳，或者造不出只差一处的 x′，就把差的那一样具体写出来（缺哪台机器的日志、缺哪个版本的基线），这句话只写到"X 和 Y 一起出现"这一级。
   → 留下 `causal_query`：X=x 与 X=x′ 这两种情况、要看的结果 Y、对象与范围、时间窗；还有带来源的事件时间线（时间戳、日志先后）。填不出："无法给出可比较的 x′／确定先后：因为缺……时间戳或基线。"

2. 记下打开过的文件、跑过的命令和它的输出 → 留下 `trace`：打开了哪些文件的哪些行；跑了什么命令、输入是什么、stdout/stderr、exit code；查过的范围，以及查出来是空的那一次；看到 X 和 Y 一起出现的地方。判据是别人照着这份记录能重跑一遍。填不出："无法运行／打开……：因为权限或环境限制，未观察到的是……"

3. 列出别的解释。
   怎么做：
   a. 按五种固定类型各问自己一句，逐个写出这一案里的具体版本：①反过来——是不是 Y 引起了 X？②共同原因——有没有一个 Z 同时造成了 X 和 Y？③挑选——我看到 X 和 Y 一起出现，是不是因为我只看了某些情况？④测量——X 或 Y 有没有记错、算错？⑤巧合——两件事一起出现，有没有可能只是碰上了？某一类给不出具体版本的，写"此类无"。
   b. 对每个具体的别的解释，照『逻辑推理』（logical-reasoning）第 3 步 d 写一句「如果它是真的，我会看到 ___；如果我的解释是真的，我会看到 ___」。两个空必须不一样；写不出不一样的，标"分不开"。
   c. 按查起来最便宜的顺序，去查那句话里的"会看到"，查到什么贴什么。
   d. 做不到时：某一项查不动（要权限、要别人的数据、要重现条件），写下它要什么才查得动，标成"没查"。清单里还留着"分不开"或"没查"的项时，这句话不升级措辞，停在第 2 步的级别。
   → 留下 `rivals`：类型｜具体解释｜两边各会看到什么｜查了没有、看到了什么。填不出："现有数据不能区分 H1 与 H2：因为两者预测相同，缺……测试。"

4. 做一次干预；不能做实验的话，就说明为什么从观察也能推出因果、靠的是哪些假设。
   怎么做：
   a. 先跑基线：什么都不改跑一次，把 Y 记下来。做到什么算完成：这份记录里有命令、输入、stdout/stderr、退出码，不是一句"跑通了"。
   b. 只改 X 这一处，别的都不动，再跑一次，记 Y。做到什么算完成：把这次改了哪些地方列出来（`git diff` 之类），里面只有第 1 步定下的那一处；多出别的改动，这一次不算数，撤掉多改的重来。
   c. 重复：照 b 的改法、同样的输入，至少再跑一次。做到什么算完成：两次的 Y 一致；不一致就把两次都记下来并写"结果不稳定"，成功的和失败的那次一起留。
   d. 再跑一次故意不改 X 的：X 保持不变，但把 b 里顺带做过的别的动作（重启、清缓存、换时间、换机器）照样来一遍，看 Y 变不变。看到什么怎么办：这一次 Y 也变了，说明这变化不是 X 带来的，回到第 3 步补一个别的解释；Y 没变，把这次的记录也留下，它是“只改 X 才变”的那半边证据。
   e. 把四次的 Y 并排写下来：基线、只改 X、重复、不改 X。再写一句比较结果：在什么范围内，Y 从什么变成了什么。
   f. 不能干预时（改不动、动了会出事、事情已经过去了），改做这五件事：
      f1. 画谁影响谁：把 X、Y，和你已知会影响它们的东西各画一个点，用箭头写"这个影响那个"，每根箭头旁边写一句依据（哪份记录、哪段代码、哪条常识）。没有依据的箭头不画，或者标成"猜的"。
      f2. 找绕路：除了你要证的 X→…→Y 那条路，还有哪些路能让 X 和 Y 一起动——最常见的是有个东西同时指向 X 和 Y。每条绕路写成一行。
      f3. 对每条绕路写怎么堵：要么"只在这个东西取同一个值的那些情形里比"（只比同一个版本、同一台机器、同一类输入），要么"把它的数据拿到，分开来看"。写清用哪一种，以及堵完之后还剩多少可比的情形。
      f4. 堵不住的绕路（数据拿不到、值分不开）逐条写成"无法检验的假设"：这条假设说什么、它要是不成立结论会变成什么。
      f5. 写最后一句：在上面这些假设都成立的前提下，X 对 Y 的作用为什么还能从这些观察里看出来——指明比的是哪几组、比的是什么。
   g. 做不到时：既不能只改 X，也画不出有依据的那张图，就写下最接近的能做的测试是什么（在测试环境重放、找历史上 X 恰好不同的那段时间来比），这句话停在第 3 步的级别。
   → 留下 `causal_test`：基线、只改 X 的那一次改动、重复跑一遍、故意不改 X 再跑一遍看 Y 是不是真的没变、Y 的比较结果；不能干预时改为留下 `identification`：你假定谁影响谁的那张结构、调整了什么、哪些假设无法检验、在这些假设下 X 对 Y 的作用为什么还能从观察里认出来。填不出："无法单独改 X：因为……；最接近的可执行测试是……"

5. 让从 X 到 Y 的每一步都有证据，再看改掉之后还复发不复发。
   怎么做：
   a. 把过程拆成一串点：X→M1→M2→…→Y。每个中间点要是能被看到的东西：哪个函数被调用、哪个值变成了什么、哪条消息被发出、哪个文件被写。做到什么算完成：相邻两点之间只发生一件事，再拆就拆不动了。
   b. 一根箭头写一行，行里必须有出处：`M1→M2｜依据：<文件路径:行号 或 哪条命令的哪段输出>｜这段出处怎么说明这一步`。做到什么算完成：把这一行给别人，他照着出处能自己看到这一步；只靠"于是""因此"连着、没有出处的箭头，标成"缺观测点"。
   c. 缺观测点的箭头先想办法补：加一条日志再跑一次、在那一步停下来看、把中间值打印出来、翻已有记录里能证明这一步的那一段。补上了就把出处填进去；补不上就停在这根箭头前面，它后面的箭头都不算数。
   d. 做防住测试：先写下"当初出问题的那个情形"是什么——哪条输入、哪个操作顺序、哪个环境；不改动的时候先把它跑一遍，确认它现在确实还会出问题。做到什么算完成：有这份失败前的记录；没有它，改完之后不出问题说明不了任何事。
   e. 把候选那一点去掉或者改掉，再把 d 里那个情形原样跑一遍，记下 Y。做到什么算完成：这次改了哪些地方列出来，里面只有候选那一处；同时改了几处的，一处一处来，否则不知道是哪一处防住的。
   f. 写清这次防住测试跑在什么范围里：哪些输入、哪些版本、跑了几次、有没有别的同类情形也跑了。做到什么算完成：这个范围写进了要落笔的那句话里；范围写不出来的，这一步不算做过。
   g. 记下改完之后有没有别的东西跟着变了：别的用例、别的输出、别的时间开销，看到什么写什么。
   h. 做不到时：某根箭头补不上出处，或者当初那个情形重现不了，就写下停在哪根箭头、缺哪个观测点或哪个重现条件，并且只写"促成因素"或"候选干预点"，不写根因。防住的证据齐了但只在很窄的范围里跑过，就把那个范围写进句子。根因可以有好几个；一个都定不下来时写"未定"。
   → 留下 `chain_prevent`：X→M1→…→Y，每一步都指回第 2 步记下的某一段（哪个文件、哪条命令的哪段输出）；改掉候选点之后，同类结果在写明的范围内不再出现的复现或回归证据。填不出："无法验证 M1→M2 或复发：因为缺……观测点，所以停在……"

6. 按实际走完的步数挑措辞 → 留下 `claim_wording`：要写的那句话，和它依据的最高一步。走不到，就按实际走到的那一步的级别写。填不出："我要写的话需要走到第 N 步，实际只走到第 M 步，缺……"，句子按第 M 步的级别写。

追究责任另加一步（只在要写"责任在谁"时）：查当时适用的职责和当时的记录。
怎么做：
a. 找适用职责的原文：打开当时生效的那一份——合同、政策、岗位说明、写清谁负责哪块的文件或消息——抄逐字片段，附路径和生效日期。做到什么算完成：这份东西在事情发生的那个时间点已经生效；只找得到事后修订的版本，就写"找不到当时生效的版本"。这一项只填这里抄到的那份原文；手上只有职位名、这段代码是谁写的、结果有多糟这三样时，这一项写填不出。
b. 定控制范围：写出这个人当时能自己改、自己决定的是哪些——有没有那个权限、有没有那个访问、要不要别人先批。每条给一个依据（权限配置、审批记录、当时的对话）。做到什么算完成：他管不到的部分也写出来了，明确标成"不在他能改的范围里"。
c. 定当时能知道什么：只用事情发生之前就已经存在的记录——那时告警响没响、文档里写没写、有没有人告诉过他、他自己当时写过什么。做到什么算完成：每一条的时间戳都早于那个时间点；拿事后才有的信息说"他本该知道"的，划掉。
d. 列当时能选的别的做法：至少写出一个他当时真做得到的另一种做法。做到什么算完成：这个做法在 b 的控制范围里、在 c 的知情范围里、在当时的时限里做得完，而且能防住或者减轻第 5 步里那个结果。一个都写不出来，就写"当时没有可行的别的做法"，这句话本身就是这一步的结论。
e. 写他实际做了什么或者漏了什么：抄当时的记录（提交、审批、消息、值班记录），逐字加时间。再写这件事落在第 5 步那条链的哪一环、对结果起了多大作用，指回那一环的出处。
f. 做不到时：a 到 e 里有任何一项填不出，就不写责任的话，只写因果那一层的结论，并写明缺的是哪一项。
→ 留下 `responsibility`：适用的合同、政策或岗位权限；当事人能控制的范围；当时他能知道的信息；当时他能选的别的做法；他做了什么或漏了什么，这对结果起了多大作用。填不出："无法建立责任归属：因为找不到适用职责／控制权／当时知情证据，缺……"。查清了因果贡献，仍然不可以写谁的责任；责任的话只有走完这一步才可以写。

## 措辞阶梯（第 6 步照这张表选）

| 走完 | 才可以写 |
|---|---|
| 第 1–2 步 | X 早于 Y；X 和 Y 一起出现；X 是候选因素 |
| 再加第 3 步 | 目前最站得住的因果假设 |
| 再加第 4 步 | 在 X 有和没有这两种情况下、并接受假设 A，改 X 对 Y 有因果影响 |
| 再加第 5 步里每一步的证据 | 在……范围内，这一次的 Y 是 X 造成的 |
| 再加第 5 步里不复发的证据 | 根因；证据只到这里，就写促成因素或候选干预点。根因可以有多个，也可以写"未定" |
| 再加追究责任那一步 | 责任在谁 |

这句话同时也触发「逻辑推理」（logical-reasoning）或「证据与核验」（evidence-and-verification）的阶梯时，三处各算一级，按最低的那一级写。

做到了：这句话里每个缺了它结论就变的词，都能指回上面某一步留下的东西；没走到的步都写成了"无法……，缺……"；句子已经降到实际走完的那一级。

为什么：一个故事讲得通，不等于别的故事讲不通，所以措辞只能强到你实际走完的那一步。

## 每一步来自哪个方法

- 第 1 步 ← 明确的因果对照（Pearl）：x 与 x′、Y、对象范围、时间窗是提出一个因果问题的最低条件，缺一样就没有可回答的问题。
- 第 1 步 ← 车马之问（Hill 考量里的时间方向）：先后只能靠时间戳、日志和前瞻记录定，不靠事后讲故事的顺序；而且 X 在前只排除反过来这一种。
- 第 2 步 ← 外部反馈优先（CRITIC）加过程审计（CausalityCheck）：能让别人重跑的原始输出才算证据；答案对不对要看过程记录，不看结论本身。
- 第 3 步 ← Hill 考量：问题始终是别的解释是不是一样可能，所以要比各个解释的不同预测，不是笼统说"也许还有别的原因"。
- 第 3 步 ← 因果分解（CausalCoT）：把问题拆成能逐个检查的东西——五种类型、各自的不同预测、查证结果——不是拆成更长的一段话。
- 第 4 步 ← 因果三阶（Pearl ladder of causation）：干预层的问题不能只拿相关层的证据回答，所以要么真的只改 X 跑一次，要么写出让观察也能认出这个作用的那些假设。
- 第 5 步 ← 机制逐边（Russo–Williamson：概率差异与机制证据互相支撑）：每根箭头都要指回一段实际记录，中间靠叙述连起来的不算。
- 第 5 步 ← 根因的预防定义（NASA）：改掉它、同类结果在规定范围内不再发生，才叫根因；根因可以有多个，也可以诚实写"未定"。
- 第 6 步 ← 上面几种方法的分界合并成的措辞阶梯：每一级词只由已经走完的那一步解锁；这张对应表是把这些分界排到一起得出的，不是某一本书的原话。
- 追究责任那一步 ← 原因调查与追责分开（NASA 的事故调查标准）：查清原因不授权写责任，责任要另外找当时生效的职责、控制范围、当时能知道的信息和当时能选的别的做法。

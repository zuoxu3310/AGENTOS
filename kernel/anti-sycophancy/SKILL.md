---
name: anti-sycophancy
description: Use when about to settle a judgment - a reading of a request, a review of someone's work, a recommendation - while a second position on the same question is on hand and there is pull toward the one that is easier, more senior, or one's own; before any conclusion is written.
---

# 反谄媚（anti-sycophancy）
用到：逻辑推理（logical-reasoning）第 2、3 步；呈报（report-to-user）第 3 步；论证（argumentation）；读法与契约（reading-and-contract）第 5 步。
用于：手上有一件要下判断的事（对一条请求的读法、对一份工作的评价、一条建议）和同一件事上的两个说法——自己的一个，和第二个（自己写的另一种，或者别人独立写下的），标成 A 和 B；要产出一份把先入之见摆到纸面上的记录，交给后面下结论的那一步。

何时：要下结论之前，手上有第二个说法；结论还没写。这一遍只走一次，写完就交出去，不和对方来回辩论。

第二个说法是别人写的时候，它是那个人在没看过自己这份时独立写下的，不是同一个人扮出来的反方；是自己写的另一种时，它就是「读法与契约」（reading-and-contract）第 5 步留下的 `alternative_reading` 那一类东西。

字段三态：填了（带来源：用户原话的逐字片段、打开过的文件、命令输出）／填不出（带原因和缺的证据）／不适用（带依据）。

走法：

1. 把用户这条消息重述成一版最强、最完整的请求。
   怎么做：
   a. 从用户原话里提取五样：要的结果、结果落在什么东西上、边界（能动什么、动到哪儿为止、给了多少）、怎么算完成、哪些选择仍然归用户自己定。做到什么算完成：五样各占一行；原话里出现的否定句、例外和范围词（只、全部、除了、最多）都有一行接住。
   b. 每一样后面附上它所依据的用户原话逐字片段。做到什么算完成：抄下来的片段拿回用户消息里能逐字搜到。
   c. 原话里没有、而为了让这一版读得通补进去的话，一律在前面标"推断"，并写清它是从哪一句原话推出来的。做到什么算完成：这一版里的每一句，要么带原话片段，要么带"推断"两个字。
   d. 结果、完成条件、边界这三样里，凡是怎么读都从原话恢复不出来的，写 `could_not_ground` 加上缺的是什么。常识、惯例、"一般都这么做"不拿来顶替。
   e. 删掉语气词、客气话和放在哪儿都成立的修辞；会改变范围、会改变风险、会改变某件事归谁定的限制，一句不删。做到什么算完成：删掉的每一句，删前和删后要做的事是同一件。
   f. 反事实自查：把这一版念一遍，问一句——同样这几句原话，如果指向的是另一个结果，我会不会仍然这样读？答得出"不会"的那几处，写下是哪一句原话被自己读偏了，回到 a 把那几行重提取一遍。
   g. 这一步只写一版重述，不在这里选 A 还是选 B。
   h. 做不到时：五样里恢复不出来的那一样按 `could_not_ground` 写，其余照常写完。
   → 留下 `strong_request`：结果｜对象｜边界｜完成条件｜归用户定的选择；另留 `trace[]`：成分｜用户原话逐字片段｜状态〔有原话／推断／`could_not_ground`〕。填不出：「could_not_ground」＋写明缺的是哪一句原话。

2. 给 A 和 B 各写一份文本允许的最有力的版本，两侧同样六格。
   怎么做：
   a. 先固定这一侧的结论：用一句话写出按这一侧，接下来要做的是什么。
   b. 回到用户消息，找出这条结论所依据的那一句原话，逐字抄下来。做到什么算完成：抄下来的片段是用户原话的精确子串。一句可依的原句都找不到的，这一侧按填不出写。
   c. 补前提：这一格照『逻辑推理』（logical-reasoning）第 2 步写——把 a 的结论当那一步的结论、b 的原句当它的原文，写出 `warrant`：前提 P1…Pn（每条过了可接受、相关、够不够三查）、从前提走到结论的那一步理由、成立条件。每条前提前面标"假设"。做到什么算完成：每句都过了这一关——用户原话、用户给的上下文或者打开过的文件里有东西支持它。过不了的那句，不补。
   d. 补完念一遍，把属于"用户没这么说过、不过这样写更有力"的那几句挑出来，三条查法：这句有没有对得上的用户原话片段；这句有没有标成"假设"；去掉这句，这一侧的结论还立不立得住。三条都落不到实处的那几句，删掉。做到什么算完成：留下的每一句，要么带原话片段，要么带"假设"两个字。
      这一侧的作者认不认这一版，另记一栏，只有三种填法：①作者本人确认过——写下他确认的那句话，和这句话出自哪里（哪条消息、哪个文件）；②作者没到场，但用户原话或打开过的文件里的材料撑得住这一版——指到具体位置；③联系不到作者，材料也撑不住——写"无法核对作者"。自己念一遍觉得"他应该会同意"，落不进这一栏。
   e. 把补进去的每句假设对回用户原话，看有没有引进用户没给的目标、没给的限制、没给的完成条件。有一句是，这一版作废，回到 c 重写——补的是没说出口的前提，不是新的主张。
   f. 每一侧再写两格。第一格，这一侧要面对的最难的一样事实：这一格照『逻辑推理』（logical-reasoning）第 3 步写——对 c 的 `warrant` 写出 `counter`：反例或相反解释、把两者分开的观察、做没做、结果；把 `counter` 里对这一侧最不利的那一处抄成用户原话片段或者指到文件的哪几行，再写一句为什么这一样还不足以把它推翻。第二格，这一侧的成立范围：直接抄 `warrant` 里的成立条件——它把用户的哪一段话读成了全部意思，出了什么条件就该换一种说法。做到什么算完成：最难的那一样是从材料里指出来的，不是自己编的一句；成立范围写得出一个具体条件。
   g. 两侧都写，六格同名同顺序。两个说法都没有署名，所以自己不同意的那一侧也照 a 到 f 走一遍。同样的格子，字数可以不一样：一侧只能靠一堆没依据的假设才立得住的，照样写下它最强的那一版，同时把假设那一格里的每一条都摆出来。
   h. 做不到时：那一侧写"文本不支持。"，并写明是没有原句可依，还是被用户原话直接排除。现有原话只撑得起一个和作者目标明显冲突的弱版本、要加强它就得替作者添一个他没承诺过的目标的，写 `could_not_steelman` 加上缺的那一环。
   → 留下 `reading_A` 和 `reading_B`，各六格：结论一句｜直接依据（用户原话逐字片段）｜从原话走到结论的那一步理由｜必要假设（每条标"假设"）｜最难的一样事实和它为什么还推翻不了这一侧｜成立范围；每一侧另附 c 写出的 `warrant`、f 写出的 `counter`，以及 `author_test`〔作者本人确认过／材料撑得住／无法核对作者〕。填不出：「文本不支持。」＋写明是没有原句可依还是被用户原话直接排除，或者 `could_not_steelman`＋缺的那一环。

3. 写出真实分歧，再挑一个能把判断掰过去的变量。
   怎么做：
   a. 先写一句不谈措辞的分歧：按 A 要做的是 ___，按 B 要做的是 ___，这会改变 ___。做到什么算完成：三条横线上填的都是具体的东西——要交出的东西、要动的文件、要用到的权限、完成条件里的哪一条，至少各点到一样。
   b. 检查这条分歧是不是只是换了个说法：把 A 和 B 各自要交的东西、要动的文件、要用的权限、完成条件这四样并排看一遍，四样全一样的，写 `wording_only`，这一步到此为止。
   c. 把所有可能把判断掰过去的东西列出来，从中挑一个在 A 之下和在 B 之下预期差得最开的。做到什么算完成：挑中的那一个，说得出另外几个为什么预期差得更小。
   d. 把这个变量写成五栏：可能的取值｜取到这个值时倒向哪一侧、为什么｜谁能观察到｜通过什么取得（用户原话的哪一句、哪个文件、跑哪条命令、查哪个外部事实、还是问用户）｜当前状态〔已观察／未知／观察不到／不区分〕。第二栏和第五栏照『逻辑推理』（logical-reasoning）第 3 步 d、e 写：那句「如果 A 对我会看到 ___；如果 B 对我会看到 ___」，和做没做、结果是什么。做到什么算完成：五栏没有一栏空着；哪个取值倒向哪一侧，在看到结果之前就写好。
   e. 拿变量的取值试一遍：把它换成另一个取值，接下来要做的事变不变？两个取值下要做的事是同一件，这个变量掰不动判断，回到 c 另挑一个。
   f. 做不到时：两个各自独立、任何一个单独变了都能改变结论的条件同时摆在那儿，压成一个就不老实了——写 `could_not_identify_one_flip_variable`，把两个都写出来。变量只写得出"可信度""整体质量""用户其实更在意什么"这类指不到观察方式的词，写 `could_not_operationalize`，并写明缺的是哪一样：谁观察、从哪儿取得、还是可能的取值。
   → 留下 `real_disagreement`：按 A 要做的｜按 B 要做的｜改变的是哪一样；另留 `flip_variable`：名字｜可能的取值｜取到这个值倒向哪一侧及理由｜谁能观察｜怎么取得｜当前状态。填不出：`wording_only`＋写明四样并排比过；或 `could_not_identify_one_flip_variable`＋写出那两个独立条件；或 `could_not_operationalize`＋写明缺的是哪一样观察方式。

4. 把那个变量写成一条候选，问不问交给开口回用户的那一步定。
   怎么做：
   a. 把第 3 步的变量写成一句话一个选择：用户要定的是什么｜选 A 会得到什么结果｜选 B 会得到什么结果｜为什么现有材料定不了它。做到什么算完成：写得出"用户答 X 就选 A，答 Y 就选 B"这一句；写不出，回到第 3 步 c 另挑变量。
   b. 一句话里只装一个选择，"以及""同时"这类把两个各自能单独回答的问题拼起来的写法，拆开重写。做到什么算完成：把这句话拆一遍，拆不出第二个能单独回答的选择。
   c. 选项和它们的后果照实写，各占一行，两行长度相当；哪一个更省事、哪一个更合自己那个说法，在句子里看不出来。
   d. 这一条问不问、和别的候选放在一起问哪一个，不在这里定，归『呈报』（report-to-user）第 3 步；这里只留候选。
   e. 做不到时：两个各自独立、都挡着下一步的用户决定同时在，一个问题解不开——写 `could_not_reduce_to_one_question`，把两个决定都写出来，一起交上去。
   → 留下 `question`（候选）：用户要定的是什么｜选 A 得到什么｜选 B 得到什么｜为什么现有材料定不了它。不适用：第 3 步是 `wording_only`，没有要定的事。填不出：`could_not_reduce_to_one_question`＋写出那两个各自独立、都挡着下一步的用户决定。

5. 拿自己那份没看过对方时写下的说法对一遍，写下改口记录。
   怎么做：
   a. 把自己那个说法调出来，逐字段和第 2 步的两份钢人对一遍，把自己那份里没处理过的地方一个个标出来。
   b. 每个标出来的地方先过来源关：算新证据的只有四样——自己那份里没处理过的用户原句、实际打开过的文件里的内容、跑过的命令或工具的输出、用户对第 4 步那一问的回答。这四样之外的，不算。
   c. 再过区分关：照『逻辑推理』（logical-reasoning）第 3 步 d，对这份材料写一句「如果 A 那个说法是对的，我会看到 ___；如果 B 那份是对的，我会看到 ___」。两个空写出来一样，这份材料在两个说法之下预期相同，不算新证据；两个空不一样，才算。两个空差得开不开，用"在哪一侧更预料得到"这句话说，凭手感算出来的数字不写。
   d. 划掉这几样，它们一律不算证据：对方那份出自谁手、写得更自信、篇幅更长、语气更权威、同一句话重复了几遍、两个说法哪一份排在前面、"这一份是我自己写的"、被要求"再考虑一下"。做到什么算完成：新证据那一栏里，这几样一个都找不到。
   e. 看法确实改了的，按四段写：旧看法 → 新证据（指回用户哪一句、文件哪几行、命令哪一段输出，或者用户回答里的哪一句）→ 它打中的是哪一样，写出是哪一条原话对应、哪一条假设、哪一条边界，还是完成条件里的哪一条 → 新看法。哪一段写不出，就是没改成，维持原来的看法。
   f. 再写一句没改的部分：旧看法里哪些还留着。只改被推翻的那一小块，其余照旧。
   g. 做不到时：说得出想改、说不出哪条证据能把两个说法分开，就维持原来的看法，并写明缺的是什么。新材料来源核不了，或者它只是在评价另一个说法写得怎么样，写 `could_not_use_evidence`＋写明是哪一样。
   → 留下 `mind_change`：起初那个说法〔A／B／还没定〕｜新证据｜在 A 之下预期看到什么｜在 B 之下预期看到什么｜区分得开还是分不开｜它打中的是哪一样〔原话对应／假设／边界／完成条件〕｜结果〔维持／A 改成 B／B 改成 A／收窄成某个条件下才成立／还没定〕｜没改的那部分留着的是哪些。不适用：看法没变，依据写清那份新材料在两个说法之下预期一样、分不出高下——维持是正常答案。填不出：说得出想改、说不出哪条证据能把两个说法分开，就维持原来的看法，并写明缺的是什么。

做到了：五样齐了——`strong_request` 连着 `trace`、`reading_A` 和 `reading_B`、`real_disagreement` 连着 `flip_variable`、`question`、`mind_change`；每一样要么带得出用户原话的逐字片段、文件的哪几行或者命令的哪一段输出，要么写着一条带原因的"填不出"。这一遍不声称把先入之见去掉了：它做的是把先入之见摆到纸面上——起初怎么读的、后来动没动、动是因为哪一条在两个说法之下预期不同的材料，全都留着可查。反对意见够不够格、结论怎么算，是「论证」（argumentation）那一份的事。

为什么：改口只该发生在一份材料在两种说法之下预期不同的时候；篇幅、语气、自信、谁写的、排在前面还是后面、再催一句"重新想想"，在两种说法之下预期完全一样，所以它们能改变的只有态度，改变不了判断。

## 每一步来自哪个方法

- 第 1 步到第 4 步 ← 双向钢人论证（用户定的四步协议）：先把请求重述到最强最全，再给两侧各写一份最有力的版本，再找出真实分歧和一个能把判断掰过去的变量，最后把归用户定的那一件写成一条候选，问不问由开口回用户的那一步定。
- 第 1 步 ← Dennett 转述的 Rapoport 规则：先把对方的立场重述得清楚、生动、公平，列出双方一致的地方，说出自己从对方那里学到了什么，然后才开始反驳。这四条是 Dennett 在 2013 年凭记忆写下的自己的表述，不是 Rapoport 的逐字四条。
- 第 1 步 ← "考虑相反面"的反事实（Lord 1984）：那项研究里管用的指令不是泛泛的"保持公正"，而是逐条问一句"同样这份材料，如果得出的是相反的结果，我还会不会给同样的评价"。
- 第 2 步 ← 穆勒《论自由》第二章：一个立场的最强版本要从真实相信它的人那里听来，只听己方转述一遍再顺手驳掉的那一版不算；所以并排的另一个说法是另一个人独立写下的。
- 第 2 步 ← 至少一个可信替代（Hirt & Markman）：去掉先入之见靠的是造出一个站得住的替代说法，不是机械找一个直径相反的说法；明显立不住的替代产生不了同样的效果。
- 第 2 步 ← 真实异议优于扮演的反方（Nemeth 2001）：同一份反对脚本，只改"这是真实持不同意见的人"还是"这是被指派来唱反调的人"，真实异议那一侧产生的方案更多也更好；所以这里用的是另一个人在没看过自己这份时独立写下的说法，不是同一个人扮出来的反方。
- 第 2 步 ← 宽容原则的边界（principle of charity）：前提补到文本允许为止；替作者加一个他没承诺过的目标，那是新的主张，不是更忠实的解释。
- 第 3 步、第 5 步 ← 似然比式的区分性证据（法庭科学与诊断实务）：先把两种说法写成两个相互竞争的说法，再问同一份材料在这两个说法之下预期是不是不同；预期差不多的材料推不动改口。没有可数的频率时只做定性比较，数字凭手感编不出来。
- 第 5 步 ← 保留初始判断并记录更新（超级预测）：起初那份判断留着、带时间，后来每一次更新记在它旁边，不覆盖历史。
- 第 5 步 ← 最小改变（AGM revision）：改口只改被推翻的那一小块，其余的原样保留，所以要连没改的部分一起写出来。

---
name: argumentation
description: Computes a verdict over two side-by-side positions under re-checkable rules: pass, amend one spot, or return with one question; an objection only counts if it points at exact quoted words, states the consequence for the work, and offers a minimal fix — whoever asserts must prove. Use when judging someone's reading, plan, or piece of work; use its final section when answering objections to one's own position, disposing of each one verbatim.

# 论证（argumentation）
用到：逻辑推理（logical-reasoning）第 2 步；反谄媚（anti-sycophancy）。
用于：手上有同一件事上的两个说法并排放着——一份是自己的，一份是第二个（自己写的另一种，或者别人在没看过自己这份时独立写下的）——外加原话（用户的话或材料原文），以及「反谄媚」（anti-sycophancy）那一遍留下的东西：`strong_request`（最强最完整的那一版请求）、`reading_A` 和 `reading_B`（两侧各自最有力的版本）、`flip_variable`（能把判断掰过去的那个变量）、`mind_change`（改口记录）；要产出一句结论〔通过／改一处／退回带一问〕，附理由。用这份的工作流可以把这三个词换成自己的叫法。末节写给写对方那份说法的人。

何时：要下结论之前；手上有两个说法（标成 A 和 B）和「反谄媚」（anti-sycophancy）留下的五样。

走法：

1. 逐字段对照：把两个说法里同名的字段并排抄下来，每行标一个关系〔同／兼容／冲突／遗漏〕。
   怎么做：
   a. 把两个说法里出现过的字段名列成一张表，一份有、另一份没有的字段名也各占一行，缺的那一格写"无此字段"。做到什么算完成：两份里出现过的字段名一个不落，都在表里占了一行。`worth_and_precedent`（这件事值不值得做、有没有现成的东西已经解决了它）和别的字段一样并排对照，在表里占一行。
   b. 每一格只抄原文片段，不改写、不概括、不把两句并成一句。做到什么算完成：抄下来的字拿回原说法里，能逐字找到。
   c. 逐行按下面四问的顺序判关系，先成立的那一个就是这一行的关系：①一侧那格是"无此字段"，或者只有字段名没有内容，而另一侧有内容 → 遗漏。②照 A 那格去做和照 B 那格去做，交出来的东西、要动的文件、验收怎么过全都一样 → 同；两格用词不一样不影响。③两格所说的事不能同时都对——做了 A 那格说的，B 那格说的那句就成了假的 → 冲突。④两格能同时都对，而且把 B 那格的内容加进 A 那个说法，A 原来要做的事不变，反过来把 A 那格加进 B 那份，B 原来要做的事也不变 → 兼容。`worth_and_precedent` 那一行另有两问，排在①之后、②之前：两边写下的结论不是同一个（不做／用现成的 X／要做）→ 冲突；两边的结论是同一个，而一侧的三层查找（本项目自己以前的记录／已经成熟的现成做法／现成的零件拼起来）里有一层另一侧根本没查过 → 那一层记遗漏，并写明是哪一层。
   d. 回头看一遍标成"同"的行：说不出两边要做的事一样在哪、只是读着差不多的，退回 c 重判成兼容或冲突。做到什么算完成：每一行标成"同"的，都举得出交付物、要动的文件、验收这三样里至少一样，两边确实相同。
   e. 做不到时：这一行判不出关系，写"此行不可比对"，并写明是哪一侧没有这个字段，还是那一格的字读不出意思。两个说法字段名完全对不上的，按内容配对；配不上的行照样写"此行不可比对"。
   → 留下 `field_map[]`：字段名｜A 的原文片段｜B 的原文片段｜关系。填不出：「此行不可比对」＋写明哪一侧没有这个字段，或者格式读不出来。

2. 从第 1 步的表里挑出会改变要做的事的差异。
   怎么做：
   a. 只看关系是冲突或遗漏的行。标成"同"的行跳过；标成"兼容"的行按第 1 步的判法本来就不改变对方要做的事，也跳过。
   b. 每一行分两句写：按 A 要做的事、按 B 要做的事。做到什么算完成：每一句都点到了这四样里至少一样具体的东西——要交出的东西、要做的动作、要打开或要改的文件、验收里哪一条怎么算过。
   c. 把这两句摆在一起，指出不同的到底是哪一样：哪个交付物、哪个动作、哪个文件、哪一条验收。指得出来，这一行才进 `live_diffs[]`。`worth_and_precedent` 那一行是例外：关系判成冲突或遗漏的，一律进 `live_diffs[]`。什么都不做、把现成的 X 拿来用、自己动手做，这三样本来就是三种不同的活。按 b 写两句时，直接写清两边各是这三样里的哪一样。
   d. 划掉形容词：更清晰、更完整、更稳健、更严谨、更符合意图这类词放在哪一边都成立，一律划掉，改写成具体的东西。做到什么算完成：两句话里没有一个词是只说好坏、不说做什么的。
   e. 按进表的顺序给每条差异编号，第 3、4 步都用这个编号引它。
   f. 做不到时：看得出两边措辞不一样、却说不出哪个交付物或哪一条验收会不同的行，写进 `notes[]`，不进 `live_diffs[]`；所有行都这样，`live_diffs[]` 按填不出写。
   → 留下 `live_diffs[]`：来源行号｜按 A 要做的事｜按 B 要做的事。填不出：「无实质差异。」＋写明逐行比过，差异只落在措辞或详略。

3. 写反对意见，一条一条，五样都写得出来才写下一条。
   怎么做：
   a. 一条差异一条来：拿一条差异，试着写一条反对意见；五样都写得出来才写下这一条，凑不齐就换下一条差异。
   b. 第一样，反对哪一处：抄用户原话的逐字片段，再写明被反对的是哪一个说法的哪个字段。做到什么算完成：抄下来的片段是用户消息的精确子串；找不到，这条不写。
   c. 第二样，哪一种：先写出理由，再问自己一句——这条理由如果成立，那一侧的结论是变成假的，还是只是没了支撑、真假不明？①变成假的 → "说结论不成立的理由"，要写出那个让结论变假的理由本身。②真假不明 → "说理由撑不起结论"，要点名的那一步，照『逻辑推理』（logical-reasoning）第 2 步给那一侧的结论写出 `warrant`（前提、从前提走到结论的那一步理由），指出里面从哪一句前提到结论的那一步在这个情形下撑不住。③两样都不是，而是同一句原话能读出两种意思 → "缺一件只有用户能定的信息"，做到什么算完成：写得出至少两种说法，两种都有用户原话撑着，按它们去做的事互不相容；写不出两种，这条不写。④只写得出"我会换个做法""我更喜欢另一种"的，①②③一样都不是，这条不写。
   d. 第三样，根据：指回用户原话片段、打开过的文件的哪几行、或跑过的命令的哪一段输出。谁断言谁举证：意见里只要写了"漏了""错了""还有别的做法"，举证的就是提意见这一方；举不出根据，这条不写。只问"这里是什么意思"不用举证，但它只是个问题，不能单独把结论推到改一处。反对 `worth_and_precedent` 的，根据另有两种写法。①说"已经有现成的东西解决了它"的，要点出那条路径或那个工具的名字，再写出它吃进去的输入和交出来的结果，跟这个说法要做的那件事一样；名字、输入、结果三样有一样写不出，这条不写。②说"这根本不是个真问题"的，要抄出用户原话的逐字片段，再指出这段原话里没有指着任何一个现象；指不出，这条不写。这两样的举证都落在提意见的一方。
   e. 第四样，后果：写出不处理它，要做的事会怎么不同——交付物、动作、要碰的文件、验收哪一条过不了。判据同第 2 步：形容词不算。写不出具体不同的，这条记进 `notes[]`。
   f. 第五样，最小修复：写出在用户已给的材料范围内怎么改，改完说法仍然连贯可执行，且没有发明新目标、没有越出用户给的范围。属于"缺一件只有用户能定的信息"的，这一栏写"只有用户能定"＋要问用户的那一问。根据和后果都站得住、材料范围内确实给不出有限修复的，这一栏写"材料范围内无有限修复"，这一条照样写下来，第 4 步会用到它。
   g. 把不够格的分出去：只说措辞、风格、详略、个人偏好，没有指出用户给的限制被违反、没有指出完成条件过不了、也没有指出哪一步支撑失效的，记进 `notes[]`；反对的那件事在另一侧说法里别处已经写清楚了的，不写。
   h. 做不到时：逐条差异都比过、五样凑不齐一条，按填不出写。
   → 留下 `objections[]`：反对哪一处（用户原话的逐字片段）｜哪一种〔说结论不成立的理由／说理由撑不起结论／缺一件只有用户能定的信息〕｜根据｜后果（要做的事会怎么不同）｜最小修复。填不出：「没有一条够格」＋写明逐条比过的差异编号——这是正常答案。够不上一条的意见另记 `notes[]`：缺了它结论也不变的提示，不进结论。

4. 由反对意见算出结论。
   怎么做：
   a. 先数 `objections[]` 里够格的条数。一条都没有 → 通过，`verdict_basis` 写 0 条，加上已经比过的差异编号范围。差异只落在措辞、口味，或者对方说法里已经处理过的事，同样是 通过。
   b. 有够格的条，先试退回：逐条问两句话，任一句答"是"就是退回。①这条打中的是不是用户明说的目标、不能突破的限制、或者完成条件，而它的最小修复栏写着"材料范围内无有限修复"？②这条是不是"缺一件只有用户能定的信息"，留下两条文本都撑得住、要做的事却互不相容的路，其中含不可逆或对外的后果，又没有安全可退的默认做法？是退回的，把那一条能解开分歧的具体问题写进 `return_question`。
   c. 两句都答"否"，再逐条试改一处：问两句话——这条的最小修复，用户已给的材料够不够做到？改完之后整个说法还连贯、还照着做得下去吗？两句都答"够／能" → 改一处，只动被驳倒的那一小块，其余照旧。
   d. `verdict_why` 写一句能对着材料查证的话：指回触发它的那条反对意见的编号，和它反对的那句用户原话片段。写不出可查证的指回，说明第 3 步那一条不够格，退回第 3 步重判。
   e. 重算一遍：把写下的那个词盖住，只拿 `objections[]` 和 `live_diffs[]` 按 a 到 c 再走一次。做到什么算完成：算出来的词和写下的词是同一个。不一样，改的是那个词，不是规则，同时写清是哪一条反对意见被算错了。
   f. 做不到时：三个词必居其一。说不出触发它的那条反对意见，就是 通过；说不出材料范围内的最小修复，就是退回 附一问。
   → 留下 `verdict`〔通过／改一处／退回〕、`verdict_basis`（触发它的反对意见编号；通过时写 0 条与已比过的差异范围）、`verdict_why`（一句能对着材料查证的理由）；退回另留 `return_question`（一条能解开分歧的具体问题，不是退回时写不适用）。填不出：无——三个词必居其一。

做到了：四样齐了，且 `verdict` 能由 `objections` 和 `live_diffs` 按第 4 步的规则重新算一遍得出来；算不出同一个词，就还没写完。

## 写对方说法的人怎么处理反对意见

一条意见一条处置，来源不同的意见分开记。反对 `worth_and_precedent` 的意见和别的字段的意见一样，照下面同一套逐条处置。

怎么做：
a. 把收到的意见逐条编号，来源不同的分开放：不合并、不去重、不改写对方的字。做到什么算完成：每一条意见后面都跟着一条自己的处置。
b. 五条依次查，全成立才写"采纳"：①它反对的字段和用户原句都定位得到——查法：那个字段名在自己这个说法里找得到，引的用户原话拿去在用户消息里逐字搜，搜得到；搜不到就是这条不成立。②它说的那一种关系确实成立——查法：说结论不成立的，念一遍那条理由，看结论是不是真的变假；说理由撑不起结论的，找到它点名的那一步连接，看那一步是不是真的断了；说缺一件只有用户能定的信息的，把它给的两种说法各念一遍，看是不是两种都有用户原话撑着、要做的事是不是真的互不相容；念不通就是这条不成立。③意见里凡是说"某件事成立"的地方，自己都带着根据——查法：把这类句子一句一句挑出来，每句后面找它的根据（用户原话、文件哪几行、命令哪段输出）；有一句光说没根据，就是这条不成立。④后果确实改变要做的事——查法同第 2 步：按它说的改和不改，交付物、动作、要碰的文件、验收里至少有一样不同，而且指得出是哪一样；只指得出形容词，就是这条不成立。⑤最小修复没有发明新目标、没有越出用户给的范围——查法：把修复里出现的目标、限制、完成条件逐个对回用户原话；对不上的那一个就是新发明的，这条不成立。
c. 部分采纳怎么取：②③④都成立，只有⑤倒在修复铺得比需要的宽——把修复拆成几截，逐截问"去掉这一截，被反对的那一处还修好吗"；答"还修好"的那几截去掉，留下最小有效的那一截，处置写"部分采纳"。
d. 不采纳怎么写：五条里任一条不成立，或者有更强的用户原话压着（用户原话直接说了相反的话），或者自己那个说法里别处已经明确处理过——处置写"不采纳"，并写下倒在哪一条。
e. 改了的写 before → after，指到改的是哪个字段、哪一句话；不改的写具体理由，理由要指回用户原话，或者指回自己说法里已经处理过的那一处。"不需要改"不算理由。
f. 剩余分歧照原样留：这条意见仍然成立的部分单独写一句，不并进共识；对方原文逐字保留，不为了让结论一致改写或删掉。
g. 做不到时：某一栏缺了、处置写不出来，写"无法处置"＋写明这条意见缺了哪一栏。
→ 留下 `disposition[]`：意见编号｜对方原文（逐字保留）｜处置〔采纳／部分采纳／不采纳〕｜命中的条件号（不采纳则写倒在哪一条）｜改动 before → after，或不改的具体理由｜剩余分歧（这条意见仍然成立的部分）。填不出：「无法处置」＋写明这条意见缺了哪一栏。末尾另记自己的最终说法和最后结论；分歧原样留着，不并成一句共识。

为什么：反对要能指回用户原话、能说出要做的事会怎么不同、能给最小修复，否则它是情绪不是理由——所以没有一条够格的反对意见时 通过是默认，不是需要额外证明的例外。

## 每一步来自哪个方法

- 第 1 步 ← 差异账：两个说法按同名字段逐行摆开，一行只判一件事——是同、是能并存、是不能并存，还是一侧根本没有内容。
- 第 2 步 ← 实质意见与口味意见之分（PLOS 的编辑与作者指南）：只有指得出某个交付物、动作、文件或完成测试会不同的差异才往下走，形容词不算差异。
- 第 3 步 ← Toulmin 三件套（data / warrant / claim）：主张、根据、从根据到主张的那一步连接，缺哪件就反对哪件。
- 第 3 步 ← Pollock 说的两种反对（rebutting / undercutting defeater）：一种是给出说结论不成立的理由，一种是点名哪一步连接在这个情形下撑不住；只是另有偏好、另有可能，两种都不是。
- 第 3 步 ← 谁断言谁举证（pragma-dialectics 举证责任）：只问隐含前提，说明责任回到主张一方；一旦断言"漏了／错了"，举证责任在提意见的人。
- 第 4 步 ← 机械判词：结论必须能由反对意见和差异表按同一套规则重新算出来，写判词的人自己的说明不作数。
- 末节 ← 逐条回应（PLOS point-by-point）：一条意见一条处置，写改动的位置，或者不改的理由；理由成立而修复铺得过宽，只取最小有效的那一截。

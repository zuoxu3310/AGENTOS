# 证据与核验（evidence-and-verification）
用到：逻辑推理（logical-reasoning）第 3 步；因果推断（causal-inference）。
用于：手上有一件说是做完了的活，要产出一句站得住的话的时候。三种情形：准备写下"完成／通过／看到／做好了"这类话；或者手上拿着他人做出来的结果，准备拿它当结论用；或者要把交来的结果对着"什么算做完"一条条核。

何时：一句话已经到嘴边，准备说某件事成了；或者刚收到一份他人交来的结果和一句"做好了"。

走法：

1. **逐条核**：把"什么算做完"的条件（用户批过的那份清单，程序里的字段叫 `done_when`）抄成一行一条，每条自己跑一遍或者打开看一眼。
   怎么做：
   a. 抄条件。一条只讲一件能看的事；一条里出现"并且""同时"就拆开，拆到每条能单独判成或不成为止。抄完数一遍：条数跟原清单里的件数对得上。原话含糊到写不成一件能看的事的，原样抄下来，另起一行写它含糊在哪一处。
   b. 给每条条件归类，按它要拿什么去看分五类：跑一条命令能看出来（"跑得起来／测试过了／构建成功"）｜打开文件能看见（"文件里写着／改成了／加上了"）｜查一处记录能查到（"记下了／存进去了／查得到"）｜当场做一遍能看出来（"点了会怎样／调一次会返回什么"）｜回原文对得上（"引了哪份材料／有出处"）。五类都归不进的，先写出这条条件到底要看的是什么，再照最接近的一类做。
   c. 命令类：在条件说的那个目录里把命令跑一遍，留下命令原文、工作目录的绝对路径、跑它的那个程序的版本、退出码，以及 stdout 和 stderr 的原样片段。退出码留下来了，这一条才算跑过。
   d. 文件状态类：按绝对路径打开文件，把条件说的那几行原样抄出来并附上行号，同时记下这个路径存在、它是文件还是目录。条件要求内容一模一样的，再记一条内容指纹（例如 sha256）。路径在的还要多答一句：这个文件是不是这次这件活做出来的——答话写进 `method`。
   e. 记录类：把查它用的那一句原样写下来——命令、接口调用、或者路径加检索词——再把它返回的原样结果一并留下。查询那一句写出来了，这一条才算查过；写不出来的按 j 办。
   f. 行为类：把这个行为当场做一遍（跑一次、调一次、点一次），从发起到出结果的整段来回原样留下，发过去的输入和收回来的输出都在里面。
   g. 出处类：把引文放回它说的那份原文，按空白规范化后做一次精确子串查找，留下文件绝对路径加行号，或者页码与位置。出处在外面的文献或网页的，把 DOI 或 URL 解析一次，再逐项对题名、作者、年份、发表处，四项都对上这一条才算核过。这一步只证明这串字在那里；它够不够撑起结论，是第 2 步单独判的事。
   h. 分清原样和复述。原样是从终端、文件或者接口里逐字拷下来的字，一个字没动，中间截断的把截断处标出来；复述是用话说它是什么（"测试都过了""文件已更新""看起来正常"）。判法：把这段字放回它原来的地方，能一字不差找到的是原样，找不到的是复述。原样进 `raw_output`；复述的那一份进第 3 步的 `hearsay[]`。
   i. 重跑不安全的（会改动线上数据、会花钱、会发出去收不回、会盖掉用户手里的东西，或者只在当时那个环境里成立）：这一次不跑，改留三样——当时那次运行留下的、不会被改写的日志的绝对路径加行号；这次做出来的东西本身（路径、类型、大小、内容指纹）；跑它的那个环境（机器、目录、版本）。三样里缺哪样，就在 `method` 里写明缺哪样。条件说的是一处改动、手上又有补丁的，用只检查不落地的方式试装一遍（`git apply --check` 之类），留下这条命令和它的退出码。
   j. 上面几样都做不成的：写出挡住的东西——权限、缺文件、缺凭据、环境起不来、要用户先做一件事——再写出拿到什么就能核，然后按下面的填不出写。
   → 留下 `checks[]`，一条一行：
   - `condition`：那条条件的原文，一字不改。
   - `method`：跑的，写命令、工作目录、跑它的那个程序的版本、退出码；看的，写文件绝对路径和看的是哪几行；查的，写那一句查询；当场做的，写做了什么；没跑的，写不跑的原因和改留的那三样。
   - `raw_output`：stdout/stderr 的原文片段，或者一份不会被改写的日志的路径；看文件的贴原样片段。粘原字；复述过、概括过的那一份归到第 3 步的 `hearsay[]`。
   - `status`：已核（这一行的 `method` 和 `raw_output` 都填上了）｜无法核｜不适用。
   填不出：写 `status: 无法核`，正文写"无法核第 N 条『<条件原文>』，因为<挡住的东西>，缺<拿到什么才能核>"。这条不在那份清单里：写 `不适用`，加上依据。

2. **逐句选格**：把准备写进回复的每句关键话单独拎出来，给每句配一格，配到证据撑得住的那一格为止。
   怎么做：
   a. 拎句子。关键话是这几种：说某件事成了的、说某样东西存在或者不存在的、说某件事是另一件事造成的、说毛病出在哪一处的、说下一步该怎么办的、要写进交接或者长期记录的。逐句拎出来，一句一行。同时分开三类各按各的写：能核的事实按下面八格走；对将来的预测，写出它的不确定和成立条件；关于好坏该不该的判断，写出依据的原则和一条说得通的相反原则。三类谁也不借谁的确定性。
   b. 每句先挑一个自己觉得撑得住的格，从这一格开始按 c 里的检验往下试：检验过了就写这一格，没过就降一格再试，试到过了为止。这句话同时触发「逻辑推理」（logical-reasoning）或「因果推断」（causal-inference）的措辞阶梯时，三处各算一级，按最低的那一级写。
   c. 八格和各自的检验（`level` 只写这八个词之一；检验里说的东西得在 `license` 里装得下）：
      - **观察到**：自己取到的原始输出里就有这句话。检验：把这句话和 `license` 指的那段原样输出并排放，这句话说的内容在那段字里逐词找得到。话写到"看到／输出里写着／文件里有"为止。
      - **支持**：证据让它更可能，另一种说得通的解释还立着。检验：这句话照『逻辑推理』（logical-reasoning）第 3 步写出了 `counter`，里面有至少一种别的说得通的解释，并写明现在还没有哪条证据把它挡掉。一种也想不出的，写下自己找过哪几处，这一格照旧只写到支持——想不出不等于它不存在。转述他人报告最高到这一格。话写到"支持／与之一致／看起来是"为止。
      - **强支持**：几条互相独立的证据指向同一条，并且写出了检过哪几种说得通的解释、各自被哪条证据挡住。检验：把证据一条条列出来，逐条写它来自哪里，来自同一次运行、同一份报告、或者同一个模型的说法合并算一条，合并之后还剩两条以上；再把 `counter` 里检过的解释一条条列出来，每条后面写是哪条证据把它挡住的。挡住的那句话写不出来的解释，让这句留在支持。
      - **最佳解释**：点名了另外几种解释，逐个写出它比那一种强在哪条证据上。检验：每一种别的解释后面都有一句"我这条比它强在哪条证据上"，并指到 `checks[]` 的第几条或某路径的某几行。有一条写不出这句比较的，这一格不成立。
      - **证明**：在写明的范围里做了完全核验，或者有权威原文。检验：范围写出来了（哪台机器、哪个版本、哪些输入、哪段时间），并且这个范围里每一种情况都核过；或者贴出权威原文的精确片段和它的位置。范围写进 `text` 里，出了范围这一格作废。
      - **因果**：这句话按『因果推断』（causal-inference）走到了第 4 步。检验：这句话的 `causal_query`、`trace`、`rivals`，以及 `causal_test` 或 `identification`，四样都写出来了、各带引用。缺一样，降到最佳解释。
      - **根因**：在因果之上，这句话按『因果推断』（causal-inference）走到了第 5 步。检验：这句话的 `chain_prevent` 写出来了，里面有改掉候选点之后同类结果在写明的范围内不再出现的复现或回归证据。没有，留在因果。
      - **完成**：只对写明的那个范围成立。检验三样：`checks[]` 每条的 `status` 都是 `已核`；`hearsay[]` 逐项问一遍"这项要是不成立，这句话还成立吗"，答"不成立"的一项都不剩；未了的事项和挡着的事各自一件不剩。三样差一样，这一格不成立。
   d. 每句话留一条别人自己能重跑出来的入口：那条命令加工作目录、那个绝对路径加行号、或者那一句查询。留不出入口的，这句改到只写自己看到了什么。
   e. 句子里的每个数字、每处事实，要么指到自己核过的那段原样输出，要么在句子里标明它是照抄别人的、自己没核。
   f. 把话改小的做法，按顺序试，哪样成了就停：换成低一格允许的说法（"完成"改成"这几条已核"，"因为"改成"与之一致"，"证明"改成"看到"）；把范围写进句子（"在<哪台机器／哪个版本／哪些输入>上"）；把下结论的那半句去掉，只留看到了什么；整句从回复里拿掉。改完回到 b 重新配格。
   g. 八格从头试到底都没过的：按下面的填不出写。
   → 留下 `claims[]`，一句一行：
   - `text`：准备写的那句，原样。
   - `level`：上面八格里的一个。
   - `license`：撑起这一格的证据，指到 `checks[]` 的第几条，或者某个路径的某几行。
   撑起来的证据到哪一格，`level` 就写哪一格；撑不住就往下挪一格，或者把 `text` 改小到撑得住。
   填不出：写 `level: 无法定级`，加上"缺<什么证据>"；这句话改成只写看到了什么，或者从回复里拿掉。

3. **标出声称**（声称：他人说过、自己没跑也没打开看过的话）：把准备交出去的那份东西从头到尾过一遍，把这类话挑出来另起一张表。
   怎么做：
   a. 逐句过。每句问一遍："这句里的事，是我自己跑过、自己打开看过、还是自己当场做过一遍的？"答不是的，划出来。
   b. 划出来的每句归到一处来源，一处对应 `who` 的一个写法：他人交来的报告或结果里的话；子代理回来的那段总结；工具自己说的状态（"已完成""成功""已写入""全部通过"——工具的状态字是它写的一句话，不是它做出来的结果）；用户口头说过的事实；旧记录、旧笔记、上一次的结论。五处都归不进的，把这句话的出处照原样写进 `who`。
   c. 测试那一段单独过一遍：测试的原样输出和退出码是自己取到的，进 `checks[]`；"所以这件事做完了"这半句是从测试跨到结论的一步，进 `hearsay[]`——除非用户要的那件事本身就是这些测试跑通。一份测试摘要（"12 passed"）也是复述，进 `hearsay[]`。
   d. 每划出一句写一行：`says` 抄原话的精确子串，一个字不改；`missing` 写出自己要核它得拿到什么——哪条命令加工作目录、哪个绝对路径加行号、哪份原文加位置。三样都写不出来的，`missing` 写"不知道拿什么能核它"，这一项照旧留在表里。
   e. 逐项再问一遍"这项要是不成立，我的结论还成立吗"。答"不成立"的，在这一项后面记下它撑着第 2 步的哪一句；第 2 步那句的 `level` 就写到完成以下的格。
   f. 一句都划不出来的：换个问法再过一遍——这份东西里，哪些字不是自己从终端、文件或者接口里拷出来的。还是一句都没有的，按下面的填不出写。
   → 留下 `hearsay[]`，一项一行：
   - `who`：某块活的执行者、子代理、工具回报、用户口述、旧记录。
   - `says`：原话片段。
   - `missing`：要自己核它，还缺哪条命令、哪个路径、哪份原文。
   填不出：没有这类项就写 `hearsay: []`，同时写 `scope`（这次过了哪些来源：哪份报告、哪几个子代理、哪些工具回报）——空表只说明这个范围里没有未核的转述。

对应到程序的表：`checks[]` 里的内容就是程序里 `integration.checks` 的内容——`condition` 对 `done_when`，`raw_output` 对 `evidence`，只有 `已核` 才让 `met` 为真，`无法核` 的原样进 `remaining`；他人交来的报告里那段 `evidence` 是他人写的一段字，先进 `hearsay[]`，自己跑过或者打开看过之后才进 `checks[]`。把各块活的结果合起来核的时候，走的也是这三步。

做到了：三张表齐了——每条完成条件都有自己的 `status` 和贴着它的 `raw_output`；回复里每句关键话都能在 `claims[]` 里找到自己那一格和撑起它的证据；自己没核过的话都在 `hearsay[]` 里，带着"谁说的、缺什么"跟交付一起走。齐了以后按这个顺序抽查一分钟：挑一句结论，看它指没指到 `checks[]` 的某条或某路径的某几行；挑一条引文，回原文做一次空白规范化后的精确子串查找；挑一个路径，看它存在、类型对；挑一条安全的命令重跑一遍，或者打开那份不会被改写的日志，对上退出码和输出；挑一处改动做一次只检查不落地的试装；最后看结论有没有超出这五样撑得起的范围，超出了就按第 2 步的 f 把话改小。碰到下面这几样先抽它：字段全是正向填满、几处证据的条数和长度整齐得像排过、写着"显然／最强／完整／已全面验证"、引文没有位置、只有摘要没有原样输出、路径不带根目录、写着通过却没贴验收检查——这几样只决定先抽哪一条的顺序，本身作不了数。

为什么：声称不是事实——测试、报告、他人的回报都只是关于结果的说法，只有自己取到的原始输出能把说法钉在结果上。

每一步来自哪个方法：
- 第 1 步 ← 审计证据等级（PCAOB AS 1105／AS 1215）：自己独立取到的原始材料压过当事人自述，所以每条完成条件都自己跑一遍或者打开看一眼，并把做法、证据、结论一起记下来，让没参与的人能复核。
- 第 1 步 c–f、i ← 可核验字段表（每类字段"填了"要装什么、拿什么机械地检）：命令留退出码和原样输出，文件留路径、类型、指纹，记录留那句查询，改动留一份能只检查不落地试装的补丁；重跑不安全的改核日志、制品和环境。
- 第 1 步 g ← 引文存在与引文支持是两件事（空白规范化后的精确子串检查；文献题名精确检索与 DOI/URL 解析、作者—年份—发表处比对）：先确定这串字在那里，再单独判它够不够撑这句话。
- 第 2 步 ← 证据阶梯：话的强度跟着证据走；撑不住的时候把话改小，而不是把证据说大。
- 第 2 步 c 的强支持 ← 一致意见不是独立证据（几个模型或代理可能共享同一偏差）：证据要来自不同的地方，才算不同的几条。
- 第 2 步 d、e ← 重跑入口与核没核过的标注：关键话带上别人自己能重跑出来的那条命令、路径或查询；没核过的数字在句子里标出来。
- 第 2 步 c 的完成一格 ← 完成之门：每条完成条件都对上证据、没有未了项、没有挡着的事，三样齐了才有"完成"，并且只对写明的范围成立。
- 第 3 步 a、b ← 自报不可靠（工具状态自报、显式的成功宣称、一次性的口头信心都可能跟外面的实际状态脱开）：工具说"已完成"、子代理说"做好了"、一句置信度，都是关于结果的说法，先进声称表。
- 第 3 步 c ← 完成之门里"测试通过所以任务完成"那一条：测试只证明它自己测到的那点东西。
- 每一步的"填不出／不适用" ← 带状态的字段（填了／填不出／不适用分开写，各带各的原因和缺的证据）：查不到和用不上是两件事，各写各的；空表只说明所记范围里没找到。
- 做到了 ← 一分钟抽查（一条引文、一个路径、一条命令、一处改动）：四样各核一遍，结论超出这四样撑得起的范围，就把结论改回来。
